# 工作原理

本文说明 Snug 的实现方式。构建、发布与代码结构见 [开发](development.md)。

## 连接判定

Snug 不接入 UU远程 的任何接口，只观察它在本机留下的三路信号：

| 信号 | 来源 |
| :--- | :--- |
| 覆盖窗口 | UU远程 在被控期间显示的窗口 |
| 控制端表格 | 通过辅助功能接口读取 UU远程 主窗口中「本机被控中」的列表，得到控制端名称与设备类型 |
| 推流事件 | 系统日志中 UURemoteServer 的屏幕捕获开始与停止 |

- **连入即时响应**：任一信号出现即视为连入。控制端为手机或平板时才创建手机屏
- **断开从严判定**，以下三条同时满足才视为断开：
  1. 信号连续缺席 1.5 秒（UU远程 切换屏幕时，覆盖窗口会短暂重建）
  2. 已过 Snug 自身加屏、撤屏后的 5 秒静默期（屏幕组合变化会让 UU远程 停流重开）
  3. 推流已停止。推流仍在、但控制端表格连续 60 秒明确显示无人时，同样视为断开，避免推流状态误判导致手机屏无法移除
- **中途启动**：监听开始时先回看最近 4 小时的推流日志，远程进行中启动 Snug 也能正确识别
- **短暂断线**：断开后 15 秒内重新连接视为同一次远程，手机屏与屏上的窗口均保留

## 手机屏

- 通过 `CGVirtualDisplay` 创建，竖向 540×950 点
- **2 倍高清**：macOS 仅在逻辑尺寸短边不小于 540 点时将 2 倍模式标记为可用，手机屏的短边正好落在这一阈值上。`maxPixels` 恰为 2 倍像素，且只提供这一个模式
- 系统未自动启用 2 倍时，交由短生命周期的辅助进程（`--set-mode`）切换。由主进程直接切换时，这块屏幕释放后需要 40 秒以上才能下线
- 创建或移除手机屏时被系统挤动的窗口，会被放回原处

## 窗口移动

- 以「进程号 + 系统窗口编号」识别窗口；位于其他桌面空间的窗口通过远程令牌定位
- 依次调整尺寸、位置、尺寸并核对结果，不符则重试
- 原生全屏与最小化的窗口先转为常规窗口，归位时恢复原状态
- 手机屏上的窗口被隐藏或关闭后，屏幕自动回到窗口列表
- 辅助功能调用的超时设为 1 秒（系统默认约 6 秒），个别 App 卡住时不会拖慢整个界面

## 还原记录

- 窗口放上手机屏之前，原始位置、全屏与最小化状态、字号级数先写入 `phone-screen.json`，复原成功后才删除；记录写不进去时不移动窗口
- Snug 意外退出时，下次启动或下次放置窗口之前按记录还原
- 窗口所属的 App 暂时无响应时不强行移动，记录保留，并在手机屏上说明原因

## 字号

- 通过 App 自身的 ⌘+ / ⌘- 调整，按键只发往该 App 的进程
- 放上手机屏时按该 App 记忆的级数放大（未记忆过则用设置中的默认级数），归位时按同样的级数缩回；不使用 ⌘0，以免清掉用户原有的字号
- 级数范围为 −4 至 +8，按 App 记忆在 `zoom.json`
- 支持 Ghostty、终端、iTerm2、VS Code、Cursor、Zed。其他 App 中 ⌘= 可能另有含义，因此不发送
- 终端按标签页记忆字号：在手机屏上切换标签页后再还原，字号可能不一致
- 浏览器按网站记忆缩放，放大会连带同一网站的其他窗口，因此不调整；网页在 540 点宽的屏幕上本身即按窄屏排版

## 手势翻译

在独立线程上监听事件，只接管 UURemoteServer 注入、且在手机屏内按下的鼠标左键。本机的触控板、鼠标以及其他显示器不受影响。

| 手机上的操作 | 翻译为 |
| :--- | :--- |
| 移动不少于 10 点 | 带相位的像素滚动；松手后按速度附加惯性，速度设有上限 |
| 惯性滚动中轻点 | 仅停止滚动，不触发点击 |
| 按住 0.5 秒后拖动 | 补发按下事件，用于拖选文字 |
| 按住 0.5 秒后松开 | 右键 |
| 其余 | 原样放行 |

补发的事件带有标记，避免被再次接管。

## 已知限制的技术原因

| 限制 | 原因 |
| :--- | :--- |
| 依赖未公开接口 | `CGVirtualDisplay` 是 macOS 的私有接口，系统大版本更新后可能变化 |
| 比例以 iPhone 17 Pro Max 为准 | 540×950 点恰好落在 UU远程 底部工具栏以外的可视区域；短边 540 点同时是 2 倍模式的门槛 |
| 部分窗口无法铺满 | App 自身限定了最小宽度（系统设置固定为 740 点、Safari 不小于 574 点），无法收窄至 540 点，靠左放置 |
| 字号放大仅限终端与编辑器 | 见上文「字号」 |
| UU远程 更新后可能受影响 | 控制端名称与设备类型从 UU远程 的界面读取，界面结构变化后可能无法读取 |
