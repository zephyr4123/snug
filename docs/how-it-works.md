# 工作原理

本文说明 Snug 的实现方式。构建、发布与代码结构见 [开发](development.md)。

## 连接判定

Snug 不接入远控的任何接口，只观察它在本机留下的痕迹。怎么观察由各家的适配器负责（UU远程 的三路信号见 [UU远程 适配](remotes/uu.md)），每 0.5 秒交给核心一份中性的观测：在不在场、认出的控制端、在推哪块屏、一段信号快照。在场只认正面证据，读不到、没认出控制端都不算缺席。核心据此判定连接，各家一视同仁：

- **连入即时响应**：一报在场即视为连入，建出屏幕列表中开着的屏（见「屏幕列表」；设为主屏的那块常驻，连入前就在，见「设为主屏」）。Snug 不识别控制端是什么设备，每块屏用什么型号由用户在列表中选定
- **断开从严判定**，以下两条同时满足才视为断开：
  1. 连续不在场 1.5 秒（UU远程 切换屏幕时，覆盖窗口会短暂重建）。推流仍在即视为远程仍在进行，不设时长上限
  2. 已过 Snug 自身加屏、撤屏后的 5 秒静默期（屏幕组合变化会让远控停流重开）
- **短暂断线**：断开后 15 秒内重新连接视为同一次远程，屏与屏上的窗口均保留；等不及的，断线期间菜单栏出现「立即结束本次远程」，点了当场撤屏还原，不再等满 15 秒（#29）
- **换手**：UU远程 同一时刻只让一台设备控制一台 Mac，第二台连上来只能「接管设备」，把前一台挤下去（实测）。接管时 UU远程 先停前一台的推流、再开新一台的，中间不到 1 秒的空档由推流层 3 秒的宽限吸收，视为同一次远程，屏不撤不建
- **几家并存**：登记了几家远控时，一次远程只归一家。未连接时归登记顺序里第一家报在场的；已连接时不换，别家也报在场只记一条日志；重连等待期里换了一家连入，仍算同一次远程，推流屏、名字改取新的一家；远程结束清空归属。只登记 UU远程 时和没有这一层完全一样
- **日志**：连入、断开各记一行，带远控的名字和信号快照（「检测到 UU 连入（overlay=否 控制端=未识别 capture=是 距上次在场 0.00s）」），排查误判时看是哪一路信号在变

## 屏幕列表

设置窗口「屏幕」页有一张屏幕列表，由用户增删，最多 4 块。每一项是一块虚拟屏：名字、方向（竖或横，添加后不能改）、型号（手机、平板或电脑的某一款，或自定义分辨率）、开关。

- **只建开着的**：远程开始时建出开着的屏，远程结束时撤掉。大多数人只开一块，和只有手机屏时一样
- **同一时间只用到一块**：UU远程 一次只让一台设备控制，多开的屏留给同一台设备横竖切换，或换另一台设备时直接在 UU远程 中选它的屏，不用改设置。关着的屏远程时不建，UU远程 的屏幕列表也更短
- **行为跟着型号的类别走**：手机、平板屏上有 App 资源库和底部小横条，放上去的窗口铺满整块屏、放大字号，开着手势时翻译手势；电脑屏上什么都不加，和一块普通的显示器一样，App 资源库从菜单栏打开（见「App 资源库」）
- **改型号即时生效**：屏在线换成新比例的模式表，不掉线、编号不变（见「型号」）；改名下次建屏时生效（名字在建屏时写进屏幕身份）
- **从 2.5 升级**：原来的手机屏迁成列表的第一项「Snug 手机屏」，竖屏、型号和开关照旧，屏幕身份不变

## Snug 的屏

- 通过 `CGVirtualDisplay` 创建，方向和比例按这块屏的型号计算（见「型号」），没选过型号时为 540×950 点的竖屏
- **身份**：每块屏一组固定的身份（厂商、产品、序列号），竖屏、横屏用不同的产品号；序列号从未用过的号段里分，删掉的屏不复用。从 2.5 迁来的手机屏沿用原来的身份，系统按身份记住的档位、颜色描述文件照旧
- **2 倍高清**：macOS 仅在逻辑尺寸长边不小于 800 点、短边不小于 525 点时将 2 倍模式标记为可用（实测，与像素上限无关）。基准宽度取满足这一条件的最窄一档，手机竖屏另外不窄于 540 点（和 2.5 一样）
- **多档分辨率**：建屏时登记基准宽度至其 2 倍、每 10 点一档的模式，宽高比相同。像素上限竖屏固定为 2160×4320、横屏固定为 6144×3840，框住所有比例，每一档都有 2 倍模式；换比例不必更换屏幕身份
- 系统按其记忆的档位上线（首次为最宽一档），上线后切回基准宽度。换档交由短生命周期的辅助进程（`--set-mode`）完成；由主进程直接切换时，这块屏幕释放后需要 40 秒以上才能下线
- **几块屏一起建、一起撤**：加屏、撤屏都会让 UU远程 停流重开、让系统重排屏幕，因此要建的几块一次建好，要撤的一次撤掉，撤完再建。快照、善后按整组做一次；加屏失败的重试次数、撤屏前的最短在线时间每块屏各算各的
- **不影响其他屏幕**：macOS 按「当前连接的这组屏幕」分别记住每块屏的显示模式（含刷新率），屏幕组合一变就套用新组合记住的那份。远程期间主屏的模式若被临时改过（#13 中为 30Hz，由谁改动尚未确认），系统便记在「没有 Snug 屏的那组」名下，Snug 的屏移除时会把主屏拨回去。因此创建、移除前记下各窗口位置与其他屏幕的模式（写入日志），完成后先把被改变模式的屏幕设回原来的模式（经辅助进程 `--restore-mode`；分辨率一变窗口会再被挤动），再把窗口放回原处。期间拔掉或新接入的屏幕不动。镜像中的从属屏不记、不设：它的模式与位置跟着主控屏，单独设模式会失败，单独设位置会把它拆出镜像，管住主控屏即管住整组（#43）。判断与匹配按分辨率、缩放、刷新率进行，与系统记录的口径一致；模式编号会随屏幕组合重排，仅用于在属性相同的几档中挑回原来那一档
- **等屏真正下线**：系统在下线那一刻才挪窗口、改模式。释放后通常 0.1 秒下线；显示器睡着时（例如远程结束后 Mac 锁屏，几秒内显示器就会睡）要等唤醒才下线，可能是几小时后（实测）。因此移除只负责释放，等不到下线就记下，真正下线时（屏幕配置变化时，另有每 2 秒一次的检查兜底）再做上一条；期间再次创建同一块屏的，放弃旧的这一笔
- **永久配置**：系统套用旧模式时会同时写入永久配置（实测只在当前登录内设回，磁盘上记录的仍是旧模式）。远程结束后移除的，设回时也写入永久配置。创建时，以及远程中移除时（在手机上退出、关闭开关、删除），其他屏幕可能处于远程用的临时模式，设回只对当前登录生效；远程中移除过的，等远程结束（UU远程 已还原）、显示器醒着时，把其他屏幕此刻的模式写入永久配置
- 显示器睡着、屏尚未下线时退出 Snug，或远程中途退出 Snug，上述设回不会发生
- **撤屏前清场**：Snug 放上去的窗口按还原记录放回原位；其他留在这块屏上的窗口（中心落在屏内的，例如在电脑屏上直接打开的 App），挪到主屏居中、不大于主屏，再撤屏。不清场的话系统会把它们挤到别的屏的角落
- **指针跟着回家**：撤屏前指针若停在这块屏上，先带回主屏中央（主屏同时也是要撤的那块时，带回另一块留下的屏），以免屏撤掉后指针落在不属于任何屏的坐标上；断开后的重连等待期里每拍同样检查一次（设为主屏的那块除外）：UU 断开后不再移动指针，屏却仍在，指针停在本机看不见的屏上即找不回鼠标（#29）
- **在手机上退出**：手机、平板屏 App 资源库右上角退出这块屏（再点一次确认）后，窗口归位、屏移除，本次远程内不再创建，其他屏不受影响。远程结束后恢复（设为主屏的那块，远程结束即重新建好、设为主屏）；在设置中关闭再打开这块屏也会恢复。远程刚结束、屏尚在移除时的退出不计入，以免影响下一次远程

## 设为主屏

可选，默认「不改」。设为主屏的那块屏常驻：不等远程，Snug 启动（或在设置里选定）时就建好、设为主屏，一直保留到取消设为主屏或 Snug 退出。

- **为什么常驻**：UU远程 每次新连接都从连接那一刻的主屏开始推流（实测，它不记上次选的屏，也不跟指针），之后主屏再变也不切。Snug 只能从 UU远程 留在本机的窗口与推流日志察觉连接，察觉时 UU远程 已在推 Mac 屏，连上后再建屏、设主屏都晚了。屏在连接前就已存在、已经是主屏，每次连接才直接进入（11-18 实测：两次全新连接，第二次距上次远程结束 34 秒，一开始推的都是这块屏；#28）
- **代价**：主屏上的程序坞、新开的窗口、系统提示与锁屏登录框都在这块屏上，本机看不到；设为主屏时，原主屏上的窗口被系统整体换到这块屏上。远程时锁屏，登录框在这块屏上，可在控制端解锁（实测）。适用于不接显示器或以远程为主的 Mac，设置里选定时先确认
- **取消**：设置里改回「不改」；菜单栏「取消设为主屏」（菜单栏在每块屏上都有，本机也点得到）；手机、平板屏当主屏时，App 资源库右上角「取消主屏」。远程中取消的，这块屏留到远程结束再撤
- **远程结束**：这块屏不撤、仍是主屏，屏上放着的窗口原样留着（字号不缩回、还原记录留着），下次连上接着用；取消设为主屏、Snug 退出时撤屏，这时才放回原位。提示收掉。没人远程时资源库不刷新；在 Snug 之外关掉、又带着屏上大小回来的窗口放回原位，不再接着铺上屏。其余没设主屏的屏照旧撤
- **从 2.6.x 升级**：当时的设为主屏只在远程时生效，升级后改回「不改」，需在设置中重新选定、看过确认框才常驻
- **远程中设、取消主屏**：系统在原主屏与新主屏之间整体互换窗口，留着的 Snug 屏上由 Snug 放上、挪来的窗口会被换走；换完挪回这块屏，界面状态不变
- **设**：这块屏建好、屏幕组合稳定后，把它设为主屏（菜单栏、程序坞、新开的窗口随之过去），只对当前登录生效。设之前在内存里记下各屏原来的排列（镜像中的从属屏除外，见「不影响其他屏幕」）
- **还**：取消设为主屏、Snug 退出时，先把主屏还给原来那块，再清场、撤屏；摆回成功才清掉记下的排列，失败时留着，下次再设回时照旧按最早的那份摆
- **崩溃后**：Snug 意外退出时它的屏随之消失，屏幕组合一变，macOS 按剩下这组屏记的排列摆好，不用 Snug 再摆。所以排列只记在内存里，不落盘：落盘的记录里别的屏的位置是 Snug 的屏还在时的，系统给它们让过地方，照着摆反倒会把外接屏挪偏（11-17 实测）
- **窗口原位按没设主屏时的坐标记**：主屏的原点总在 (0,0)，设主屏时别的屏连同窗口整体平移；原主屏和新主屏之间，系统是整体互换窗口：设主屏时原主屏上的窗口搬到新主屏同一处，还原排布时新主屏上的搬回原主屏，原主屏上的反倒被换到新主屏。设着主屏时放上屏的窗口，原位换算成没设主屏时的坐标再记（在新主屏上的记成原主屏同一处），放回时换算回当时的坐标（原位在原主屏上的放到新主屏同一处，还原时随系统回到原主屏）；设回、撤屏、崩溃后系统自己摆回，都能放回原处
- 设置里改成「不改」、把这块屏关掉或删掉时，当场还原；关掉后再打开，仍按设为主屏常驻
## 窗口移动

- 以「进程号 + 系统窗口编号」识别窗口；位于其他桌面空间的窗口通过远程令牌定位
- 依次调整尺寸、位置、尺寸并核对结果，不符则重试
- 原生全屏与最小化的窗口先转为常规窗口，归位时恢复原状态
- 手机、平板屏上的窗口被隐藏或关闭后，屏幕自动回到 App 资源库；在 Snug 之外关闭的按下文「还原记录」处理
- 辅助功能调用的超时设为 1 秒（系统默认约 6 秒），个别 App 卡住时不会拖慢整个界面

## App 资源库

手机、平板屏的首页，分「运行中」与「全部」两页，顶部带搜索。手机竖屏是一列，和 2.5 一样；手机横屏和平板分左右两栏，左边 App 列表，右边选中 App 的窗口。平板屏右上角给 UU远程 的圆形菜单按钮让开 50 点。

电脑屏没有资源库面板和小横条：从菜单栏打开「App 资源库」窗口，在哪块电脑屏的菜单栏点就在哪块屏上打开、往哪块屏放（点的不是电脑屏时，往 UU远程 正在推的那块电脑屏，再不然第一块电脑屏；没有电脑屏时菜单里这一项是灰的）。每个窗口标出现在在哪块屏（在这块屏的全屏空间里、被资源库所在的桌面盖住的，标「在这块屏 · 全屏」，按钮是「退出全屏」），「放到这块屏」把窗口挪过来居中、大小不超过这块屏，不铺满、不调字号；放在手机、平板屏上的先放回原位。挪过来之前先记账（一个窗口一份，见「还原记录」），挪过来的窗口标「在这块屏」，按钮是「还原」：放回原处，原来全屏、最小化的恢复原状；这块屏撤掉、Snug 崩溃后也按账放回原处。被用户挪去别的屏、在 Snug 之外关了的不再记着（定期核对时查；撤屏前不按位置查，设回原主屏时系统会把窗口换回原主屏），不拽回来；在这块屏上直接开的窗口没有原处，没有「还原」，撤屏时照清场的规矩挪到主屏。挪过来的窗口再放上手机、平板屏，原位记录跟着走。这块屏撤掉（远程结束、关了开关）时资源库窗口跟着关掉。电脑屏上点程序坞只会在窗口原来的屏上把它提到前面，远端的人看不见别的屏、拖不了窗口，靠这个窗口一键拉过来。

- **数据来源**：在运行的 App 取自 `NSWorkspace`（有 Dock 图标的），各自的窗口为辅助功能报出的全部标准窗口，不分屏幕与桌面空间，全屏、最小化的也算；本机 App 扫描三个「应用程序」目录及其下一层子目录，另加访达，排除菜单栏与后台 App、UU远程 和 Snug 自身。界面只读一处汇总（`AppCatalog`）；放窗口、等新窗口、等退出等动作直接读系统，确认 App 退完或窗口关上时立即从汇总中去掉
- **刷新**：手机、平板屏被远端观看且列表露着，或电脑屏的资源库窗口打开且未最小化时，每 1.5 秒刷新一次运行中的 App；那块屏正在放窗口、打开 App 时暂停。每次露出时按最近使用排序一次，此后只增删、不调换位置，避免点击时列表跳动；收起后停止刷新。电脑屏的资源库窗口另要每个窗口在哪块屏，在同一轮里一次读全系统的窗口表
- **打开与新建窗口**：打开用 `NSWorkspace.openApplication`，对已在运行的 App 即「重新打开」；新建窗口用辅助功能按下 App 菜单中的「新建窗口」，按标题识别（各 App 快捷键不同：Safari 为 ⌥⌘N，VS Code 为 ⇧⌘N，终端位于子菜单内），⌘N 只是新建一条记录的 App（日历、备忘录）不按。之后每 0.1 秒检查一次，此前不在屏上、此刻在屏上的标准窗口即为新窗口，立即放上这块屏（启动最多等 30 秒，其余 10 秒）。App 已有原生全屏窗口时，新窗口出生即进入全屏，动画结束前退出全屏的请求会被忽略，因此重复请求直到生效
- **退出**：先把放在各块屏上的这个 App 的窗口归位，再请 App 退出，此后每 0.25 秒检查一次。出现「是否存储」对话框时（挂在窗口上的表单，或单独弹出的对话框），把它放上点退出的那块屏；10 秒仍未退出且没有对话框时，提示并提供强制退出。退出请求未能送达时立即提示。访达不提供退出，与 Mac 上一致
- **关闭窗口**：按下窗口自身的关闭按钮，等同点击红色按钮；放在屏上的先归位，原生全屏的先退出全屏（全屏时按关闭按钮无效）。之后按退出的方式等待：出现「是否存储」时放上这块屏，5 秒仍未关闭且没有对话框时提示无响应
- **搜索**：匹配显示名、英文名、拼音全拼与首字母（如「bwl」匹配「备忘录」），同时搜索窗口标题。仅在搜索时由列表面板接收键盘，结束后交还
- **窗口在别的屏上**：一个窗口同一时间只放在一块屏上。点另一块手机、平板屏上的它，原位记录跟着转过去，窗口直接从这块屏挪到那块屏，不先放回原位
- **名称**：Snug 只声明简体中文，系统 App 显示为「访达」「备忘录」，与界面语言一致，不随系统语言变化

## 屏幕适配

手机、平板屏的分辨率跟随屏上显示的内容：显示 App 资源库时为基准宽度（手机竖屏通常 540 点），显示窗口时为该窗口所需的一档。电脑屏建好时在基准宽度，之后 Snug 不换档，用户可在系统设置的「显示器」里自选。

- **按窗口实测**：放置窗口时先按基准宽度铺满。App 限定了最小尺寸时，窗口停在其最小尺寸上；按实际尺寸超出可放区域的比例（宽、高取较大者）选出能容纳它的最窄一档，切换后再次铺满。不按 App 预设
- **等比缩放**：各档宽高比相同，切换后画面整体等比缩小，不变形；UU远程 不重新推流，点击位置保持准确
- **切换开销**：约 0.4 秒，屏幕不掉线、编号不变。底部小横条、面板与手势判定的阈值随档位放大，在手机上的大小与手感保持不变；放大倍数按短边算（竖屏是宽，横屏是高），横竖拿着时一个点在手上一样大
- **上限**：基准宽度的 2 倍（手机竖屏为 1080 点），此时字号约为基准的一半，与 UU远程 原版查看主屏相当。更宽的窗口按最宽一档靠左放置
- 回到 App 资源库时切回基准宽度；从列表返回窗口时，先切回该窗口的档位并重新铺满，再收起列表

## 型号

UU远程 把画面等比缩放、居中铺在控制端上，比例不符时留黑边，手机上的工具栏还压在画面上。每块屏的比例因此按用户选的型号计算：

| 类别 · 方向 | 比例怎么算 | 基准宽度 |
| :--- | :--- | :--- |
| 手机 · 竖 | 屏幕高宽比，高减去上下各 91 点（UU远程 工具栏在 iPhone 17 Pro Max 上实测约 89 点，取 91 使其正好得到真机调好的 540×950，余 2 点余量） | 满足 2 倍门槛的最窄一档，不窄于 540 点 |
| 手机 · 横 | 长边减去左右共 154 点（右边 UU远程 的工具栏约 82 点，左边灵动岛那侧的暗带约 72 点，实测粗估） | 满足 2 倍门槛的最窄一档 |
| 平板 | 屏幕高宽比，不扣边（UU远程 在平板上不压画面） | 平板的逻辑短边 ÷ 1.24（1 个 Mac 点约合 1.24 个平板点，实测字大、看着舒服） |
| 电脑 · 横 | 显示器设置里的分辨率，高减去刘海那一条（MacBook 菜单栏高 33 点，实测） | 就是这个分辨率的宽 |

- **逻辑分辨率**：Apple 设备按官网公布的逻辑宽度算；安卓手机、平板没有公开的逻辑分辨率，手机按 400 点、平板按 800 点估短边
- **范围**：竖屏高宽比限定在 1 至 2 之间（折叠屏内屏扣除后比正方形更方，按正方形），横屏在 0.3 至 1 之间。16:9 等矮屏 540 点宽时高不足 800 点，基准宽度加宽到够高的一档（iPhone 8 为 620 点）
- **机型库**：`Assets/device-models.json` 是唯一的数据源，分手机、平板、电脑三段，按品牌列出机型与官网分辨率（Apple 手机、平板另有逻辑宽度，Mac 直接存逻辑分辨率和刘海高度；电脑段另有「通用」一组常见分辨率），随 App 打包。加机型、改数值只改这一个文件。测试逐条校验：竖握书写，同一段内型号与品牌均无重复，Apple 手机、平板都有逻辑宽度
- **自定义**：填写屏幕分辨率或比例（只看比例，1080×2400 与 9×20 相同），横向填写的自动转为竖向；沿用这块屏原来的类别
- **入口**：设置的屏幕详情，以及手机、平板屏 App 资源库右上角（只列手机和平板，这块屏的类别排前面），两处读写同一份配置。触屏和电脑之间不换：屏上的面板、手势跟着类别走，换类别等于换一块屏，删了重新添加。选中的机型连同分辨率一起存入配置；启动时按机型名与机型库核对，数值修正随之生效，机型库改名或删除该条时沿用存下的数值
- **即时生效**：屏在线换成新比例的模式表（屏幕不掉线、编号不变，UU远程 选中的屏幕不丢），切回基准宽度；屏上有窗口时按新比例重新选档、铺满。换不成时提示，下次加屏按新比例创建
- **UU远程 要重选一次**：UU远程 只在选中屏幕时按当时的尺寸开始推流，屏幕中途换了宽高比不会跟随（同比例换档不受影响），画面和点按位置会错开。因此换完比例后屏上提示在 UU远程 中切到其他屏幕再切回；之后按新尺寸推流，点按准确（实测）。通常只在首次使用时选一次型号
## 还原记录

- 窗口放上手机、平板屏之前，原始位置、全屏与最小化状态、字号级数先写入这块屏的 `placed/<屏 id>.json`，复原成功后才删除；记录写不进去时不移动窗口。挪到电脑屏的窗口一个一份 `placed/<屏 id>~<pid>-<窗口号>.json`，格式相同，启动时同样逐笔还原（不认识这种文件名的旧版本也照样还）。2.5 留下的 `phone-screen.json` 启动时挪成 `placed/phone.json`（手机屏已经有账时挪成 `placed/phone-2.5.json`），和别的屏的记录一样还原
- Snug 意外退出时，下次启动或下次放置窗口之前按记录还原
- 窗口所属的 App 暂时无响应时不强行移动，记录保留，并在屏上说明原因
- **在 Snug 之外关闭的窗口**（手机上用快捷键或菜单关闭、App 自己换掉窗口、App 退出）：macOS 不允许拦截其他 App 关闭窗口，Snug 发现时 App 多半已存下屏上的大小。记录不删除，转存到 `left-behind.json`，保留两周。同一个 App 的窗口带着 Snug 铺成的大小再次出现，说明 App 原样存下又原样带回，此时放回原位，字号随窗口保存的一并缩回；大小已被用户或 App 改过的不再改动，以免挪错或缩过头
- 远程中在 Snug 的屏上重新打开的，继续放在那块屏上，原位仍按最初记录的；App 关窗后 10 秒内换上新窗口的（如 ChatGPT 冷启动时会换掉第一个窗口），新窗口接着放上那块屏

## 字号

- 通过 App 自身的 ⌘+ / ⌘- 调整，按键只发往该 App 的进程
- 放上手机、平板屏时按该 App 记忆的级数放大，未记忆过则用设置中的默认级数；归位时按同样的级数缩回。电脑屏不调字号；不使用 ⌘0，以免清掉用户原有的字号
- 级数范围为 −4 至 +8，按 App 记忆在 `zoom.json`
- 支持 Ghostty、终端、iTerm2、VS Code、Cursor、Zed。其他 App 中 ⌘= 可能另有含义，因此不发送
- 终端按标签页记忆字号：在屏上切换标签页后再还原，字号可能不一致
- 各 App 把字号存在不同的地方，决定窗口在 Snug 之外关闭后如何处理：Ghostty 存在窗格里，窗口关闭即消失；终端、iTerm2 存在窗口里，App 恢复该窗口时连同大小一起带回；VS Code、Cursor 按工作区保存，重新打开时带回（屏已移除时大小会被重设，无法确认，因此关闭当时在屏上提示按几次 ⌘- 复原）；Zed 整个 App 共用，立即从它的其他窗口缩回，没有其他窗口时等它再出现窗口时缩回，Zed 退出则无需复原
- 浏览器按网站记忆缩放，放大会连带同一网站的其他窗口，因此不调整；网页在 540 点宽的屏幕上本身即按窄屏排版

## 手势翻译

在独立线程上监听事件，只接管 UURemoteServer 注入、且在开着手势的手机、平板屏内按下的鼠标左键。本机的触控板、鼠标、电脑屏以及其他显示器不受影响。

| 手机上的操作 | 翻译为 |
| :--- | :--- |
| 移动不少于 10 点（基准宽度下，宽档按比例放大） | 带相位的像素滚动；松手后按速度附加惯性，速度设有上限 |
| 惯性滚动中轻点 | 仅停止滚动，不触发点击 |
| 按住 0.5 秒后拖动 | 补发按下事件，用于拖选文字 |
| 按住 0.5 秒后松开 | 右键 |
| 轻点屏上窗口自身的关闭按钮 | 先归位、缩回字号，再关闭（直接关闭时 App 会存下屏上的大小与字号）。按钮位置在铺好窗口时读取，轻点时再向窗口服务器核对：窗口已被挪走、遮住或进入全屏的，照常点击；询问「是否存储」的窗口不拦截 |
| 其余 | 原样放行 |

补发的事件带有标记，避免被再次接管。

## 截图

设置中开启「截图」后，手机、平板屏的指示条左侧出现相机键：

- **截取**：ScreenCaptureKit 按窗口编号截取铺满这块屏的窗口，被遮挡时同样截得到。尺寸为窗口的点尺寸乘以屏幕倍率，即 Retina 原画；编码为 PNG 后清空剪贴板写入
- **权限**：需要「录屏与系统录音」权限，与辅助功能分别授予。Snug 只读取授权状态，不调用请求授权的接口：系统的授权弹窗出现在 Mac 上，手机上既看不到也无法操作。授权引导放在 Mac 端的设置页，由 PermissionFlow 打开系统设置并浮出拖拽授权的小窗口。正在运行的 App 刚获授权时，系统会提示退出并重新打开，重开后生效；开启截图时每 2 秒核对一次状态
- **浮层**：缩略图、提示与裁剪只出现在按下相机键的那块屏上。截图后浮出缩略图，5 秒后收起；结果提示 3 秒后收起。面板只有内容大小，不遮挡窗口底部的其余区域；回到 App 资源库时不显示
- **裁剪**：轻点缩略图进入，期间不自动收起，并关闭手势翻译，拖动用于调整选区。把手按手指移动的距离挪动，按下时不跳；整条边都可以抓。选区以图片中的比例记录，换档时随图片缩放，完成时换算为原图像素，四条边各自取整，不会越出原图
- **作废**：连续轻点时以最后一次为准；截图途中这块屏移除，或已进入裁剪，截好的图直接丢弃，不写剪贴板。这块屏移除时，缩略图、提示与裁剪一并收起

## 启动与更新

用户手动打开 Snug，或在运行中再次打开时，弹出设置页；开机自启时不弹出。两者通过启动时 Apple Event 中的 `keyAELaunchedAsLogInItem` 区分。版本与上次运行时不同（应用内更新后重新打开、手动替换）时，改为打开「关于 Snug」窗口，显示新版本号。软件更新、更新源在设置窗口的「通用」页。从菜单栏打开设置、关于时，窗口摆到点的那块屏正中（在电脑屏的菜单栏点，远端的人看得见）；已经在这块屏上的不挪，还在用户拖到的地方。

每次启动检查一次所选更新源的 `update.json`（开机自启时等待网络连通），不轮询。有新版本时弹出更新窗口，由用户选择更新或稍后；启动时弹出的窗口不抢占当前 App 的键盘焦点：

1. 将已安装的 Snug.app 切块，按字节范围下载本机缺少的块，逐块核对 sha256
2. 在旁边拼出新版本，核对签名满足正在运行的这份的指定要求（同一应用标识与开发者团队），且版本号与 `update.json` 一致。辅助功能授权同样依据该要求，更新后无需重新授权
3. 与已安装的版本原子对调，经正常退出流程（窗口归位、撤除 Snug 的屏、还原主屏）退出，由独立进程等待退出后打开新版本

下载与拼装期间出现任何错误，已安装的版本都保持原样。所在位置不可写或不支持原子对调、`update.json` 格式更新、签名不符时，提示用户手动下载。

## 已知限制的技术原因

| 限制 | 原因 |
| :--- | :--- |
| 依赖未公开接口 | `CGVirtualDisplay` 是 macOS 的私有接口，系统大版本更新后可能变化 |
| 一块屏不能横竖自动切换 | 换方向需要更换屏幕，UU远程 会丢掉已选中的屏幕、跳回第一块。所以每块屏固定方向，横竖都要用的各加一块，转过来时在 UU远程 中切 |
| UU远程 更新后可能受影响 | 控制端名称从 UU远程 的界面读取，推流状态来自它的日志，界面或日志格式变化后可能无法读取 |
| 未接显示器的 Mac 上，Snug 的屏会取代原来的屏幕 | macOS 只在没有任何显示器时提供一块默认屏幕，任何显示器接入（包括 Snug 的屏）即将其撤下，UU远程 中没有别的屏幕可切。目前可在屏上退出；无显示器时由 Snug 补上一块替身屏的方案待实机验证 |
| 在 Snug 之外关闭的 VS Code、Cursor 窗口，远程结束后重新打开时字号可能仍偏大 | macOS 不允许拦截其他 App 关闭窗口，关闭时 VS Code 已按工作区存下字号；远程结束后重新打开时它会重设窗口大小，无法确认是否带回了字号，因此只在关闭当时提示按几次 ⌘- 复原。开着手势时轻点窗口自身的关闭按钮、在 App 资源库中关闭不受影响 |
| 推流停止未被记录时，Snug 的屏不会自动移除 | 推流状态来自系统调试日志，格式不是公开接口。此时菜单栏仍显示「远程中」，在设置中关掉开着的屏即可还原；退出 Snug 只能暂时移除，4 小时内重新打开时，回看日志仍会判定为推流中 |
