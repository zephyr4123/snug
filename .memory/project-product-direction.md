2026-11-12 主人定下的唯一目标：让用手机通过 UU远程 使用 Mac 的体感最好，往「清晰、大、方便」做，往难的做。虚拟屏只是手段，不是目的。

主人实测的痛点（iPhone 17 Pro Max 横屏，Mac 接内建屏加 4K 外接屏）：

1. 横屏弹出 UU 键盘后只看得到 Mac 画面的上面一小条（截图里约占手机高度的 43%）。终端、聊天这类输入框通常在窗口底部，会被键盘完全挡住。
2. 字看不清时要在手机上双指放大，这个手势会带出拖拽位移。
3. 多屏时 UU 自带的切屏很好用；一加虚拟屏，macOS 就重排窗口和菜单栏，非常头疼。横屏下加不加虚拟屏，体感差别不大。
4. UU 本身已经做得不错。Snug 的价值在于叠加 UU 做不到的增强。

**已查清：UU 的键盘避让规则（2026-11-12 实测）**：手机键盘弹出的那一刻，UU 把「手机上最后点的位置」推到键盘正上方，之后只定位这一次，键盘开着时换输入框不会再跟。这完全是 UU 手机 App 自己的逻辑，Mac 这边收不到键盘弹出、收起的任何信号（录了 3 分钟 UU 进程的系统日志，没有同步出现的记录）。Ghostty 也不向系统报告光标位置（AX 读到的光标框始终为空）。结论：只要「先点要输入的那一行，再弹键盘」，体验就够用，Snug 不在键盘避让上投入。Typeless 这类第三方键盘更高，UU 按系统键盘的高度算，可能还会挡一点。

**已排除：macOS 自带的辅助功能缩放**：缩放只作用在本机的屏幕输出上，UU 抓到的是放大前的画面，手机上看不到效果。另外，开着「跟随键盘焦点」时，指针会穿不过两块屏之间的边界。

**纲领（主人定，2026-11-12）**：虚拟屏是可选功能，不是基础设施，默认关闭。UU 自己的屏幕处理（含多屏切换）非常好，不要把它搅成一团。主人「双屏 + 手机」的环境是最难的场景，就以它为开发和验收基准。基础设施只有三样：会话检测、会话生命周期、可逆调整的记账还原；虚拟屏、熄灭物理屏和后续增强都是挂在上面的功能模块。

**Why:** 主人原话：「咱们的目标就只有一个……怎么让 UU 远程在手机上使用的体感最好。不管是清晰、大，还是方便」「加了虚拟屏之后，它整个屏幕就会很怪，这个重排太复杂了」。

**How to apply:**
- 核心功能是「手机屏」，见 [[project-phone-screen-product]]。它只是多加一块非主屏，不设主屏、不关屏，原来的屏和窗口都不动，主人验证过这种做法不会搅乱 UU。
- 原版「设主屏 + 关物理屏」的虚拟屏，2026-11-12 拍板整套删除。
- 所有增强都必须「连上生效、断开还原」，崩溃后也能还原。
- 方案先用小实验验证，再动手。
