做 Snug 的任何界面（设置页、欢迎页、菜单栏、手机屏上的列表）都按这两条：

1. **图标只用 SF Symbols**：所有图标都从苹果官方 SF Symbols 里选，不自己画（包括菜单栏图标、小横条这类小元素）。页面不能只有文字，设置行、步骤、按钮都配上对应的系统图标。App 图标（AppIcon）除外。
2. **文字精简、书面、克制**：
   - 能用几个字的短词短句就不用完整的主谓宾陈述句，句末不加句号。例：「等待连接」「手机屏已就绪」「窗口已关闭」「单指滚动 · 长按选择 · 长按松开右键」。
   - 用书面语，冷静克制，不用口语。例：「还原」而不是「放回原处」，「横屏」而不是「横过来」，「稍后」而不是「稍后再说」。

3. **每个状态都讲清楚**（2026-11-13 补充）：空的、加载中、出错的，都要让人一眼看出现在是什么状态。耗时的动作（放窗口、切窗口）要有加载动画，不能点了毫无反应；出错时写明哪个 App、出了什么事、接下来怎么办（标题 + 一句说明），不用技术词（如「还原记录」「辅助功能接口」）。能返回的地方给醒目的返回键，没有可返回的就不显示，不靠晦涩的箭头暗示。

**Why:** 主人 2026-11-13 原话：「苹果有一个很重要的设计原则：每一个状态都要讲清楚。你是空的也行，出错的也行，但得讲清楚现在是什么状态」「要把报错讲得非常清楚，不要讲技术术语」「向右的箭头可以砍掉，加一个比较醒目的返回键……当这个竖屏有东西在投的时候，它就具有这个返回键；如果没有的时候就不用显示」。主人 2026-11-12 原话：「你用到的 icon 都要用苹果 SF Symbols 的官方库，不要自己绘制。因为官方库质量非常高，设计统一又好看，这样 App 页面就不只有文字了」「不要用那种完整的主谓宾陈述句，能用短词短句就用……不然整个页面看起来会非常挤」「用的语言得要书面语，得要非常冷静克制，千万不要像讲口水话一样」。

**How to apply:** 写界面文案时先写出来再砍一半；每加一个界面元素先找 SF Symbols 有没有对应的。日志和代码注释不受这条约束（注释照旧用中文讲「为什么」）。相关：[[feedback-product-thinking]]。
