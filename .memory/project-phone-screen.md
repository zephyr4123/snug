手机屏的实测结论大多已经写在代码注释和 `docs/how-it-works.md` 里：2 倍门槛（短边 ≥540 点）、按 220ppi 设物理尺寸（460ppi 的新身份永远不上线）、交给帮手进程切模式、屏幕组合一变可能退回 1 倍、加屏前给窗口拍快照、按尺寸 → 位置 → 尺寸的顺序设置并核对、先退出原生全屏、重放事件要打标记、事件监听跑在独立线程。改这些代码前先读注释，别回退。

仓库里没写、但实际踩过的：
- **UU 发来的事件**：点一下是「移动、按下、抬起」；单指滑是「按下、一串左键拖动、抬起」；双指滑是不带相位的像素滚轮；长按是「按下，约 0.7 秒后抬起」。UU 自己没有单指滚动的开关（「平板触控模式」只支持 Windows 被控端）
- **ColorSync 排障**：手机屏只用 3 个固定身份（`PhoneScreenSpec.serials`）。colorsyncd 占 CPU 时，先数 `/Library/ColorSync/Profiles/Displays/` 下的 `Snug 手机屏-*` 有没有变多（变多说明固定身份失效）。删 `.icc` 只给清单和命令，由主人自己 sudo（11-13 已清到只剩真实显示器和当前身份）
- **自测别抢焦点**：放窗口会激活那个 App，自测时别碰主人正在用的窗口
- zsh 里 `log` 是内建命令，查系统日志要写 `/usr/bin/log`
- **UU 的控制端表格只能证明有人，证明不了没人**：「本机被控中」只在被控时出现，没有「无人」的界面。4.46.0 一连上会自动切到被控页，点蓝色区域右上角的收起箭头就回到「全部设备」页，表格行消失——issue #1 的现场就这样复现。推流时长上限 2.0.1 已删（误判过两次、救场零次），别再加回来；要兜底推流卡住，在推流层取证修（CaptureSessionState），不靠表格反推

**屏幕适配实测（11-14，实验屏用测试身份 serial 999_000_001，以后实验接着用它，不再产生新 ICC）**：
- 一块虚拟屏登记 55 档（540–1080、每 10 点）全部有 2 倍；帮手切档 0.4–0.5 秒，屏不掉线、编号不变，释放仍 0.1 秒内
- 在线 `apply` 新模式表也行（1.8 秒、不掉线），但没用上：预先登记档位更快
- 主人手机实测：换档时 UU **不重建推流**（日志里没有 SCStream 停/起），画面平滑缩一下；四角点击全部命中；UU 支持双指放大
- 原生全屏绕不过最小宽度（740 的窗口在 540 屏上全屏仍是 740）；辅助功能没有「最小尺寸」属性，只能按 540 铺、读回实际大小
- 新身份第一次上线是最宽一档，之后按系统记住的那一档上线，所以建屏后要切回 540
- 旧身份的两个 ICC（`Snug 手机屏-0AD98A6A…`、`-0AF3DF3D…`）和 `Snug 实验屏-63B1145C…` 已不用，删要主人 sudo
