对外文案（README、Release 说明、GitHub 简介、官网）一律书面语：措辞正式、凝练，不用口语。主人跟我交流时说的是想法和方向，写进文档要提炼、重组、打磨，不照着原话抄。

**Why:** 2026-11-13 改 README 时连续几次被纠正：「太口语化了」「我只是跟你交流我的想法而已，并不是让你照着我的原话去抄」「这个意思没错，但是语言要更书面化一些」。致谢 UU远程 那段改了三版才过：照抄原话太单薄 → 加强了但口语（「操作跟手」「真正了不起的事」）→ 书面语（「响应灵敏」「其意义远非『难得』二字所能概括」）。

**How to apply:**
- 写之前先把主人的话拆成几个要点，再用书面语重写；每个要点要有分量（比如为什么高质量是门槛、免费为什么了不起），别只复述
- 口语词换成书面表达：「跟手」→「响应灵敏」、「放心依赖」→「可长期依赖」、「了不起」→「堪称……」
- 排版：能分点就分点，少大段文字；少量 emoji 只用在标题；README 是门面，技术细节放 docs/
- 图文要对应：图放在它说明的那一步、那句话旁边，单独一张图前面要有一句点题，让上下文接得上
