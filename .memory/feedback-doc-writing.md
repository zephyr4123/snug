对外文案（README、Release 说明、GitHub 简介、issue 回复）一律书面语、简短干练。主人说的是想法和方向，要提炼、重组、打磨，不照原话抄。

**Why:** 11-13 被连续纠正「太口语化了」「并不是让你照着我的原话去抄」；11-18 又评 README「太幼稚」「要么全是主谓宾，要么就是谓宾，口语化而且很长」，要「简短干练、官方语言」，当硬标准。

**How to apply:**
- 条目写成名词短语或「动词 + 宾语」短语，不写带主语的整句：「将这块屏设为主屏后，连接即进入这块屏」→「设为主屏后，连接直接进入此屏」；少用「你」「就」「都能」串句。和主人讨论时，示例本身也按这个标准写（2.6.2 之后的 README 是样板）
- 去虚字：「的」「了」「会」「就」「都」「也」→「均」「亦」「即」；「挪」「放到」「关掉」「见」→「移至」「关闭」「参见」。句首用「在」不用「于」，「显示于」「适用于」这类照用
- 一个条目只说一件事，长句拆成分号短句；能分点就分点；少量 emoji 只放标题；技术细节放 docs/
- 图文对应：图放在它说明的那一步旁边，单独的图先用一句话点题
- 提到第三方只陈述事实、不替人推广（不写「建议开通」、不贴优惠和购买链接），主次别颠倒；UU 收费的定稿措辞见 [[project-uu-vip]]
- 不在图标、logo 旁加角标、上标这类像批注的小字（11-26 README 顶部给向日葵加「官方适配」上标，主人评「太丑了」「风格如此突兀、像标注一样」）。身份说明放进正文，并列的条目写法保持一致
- 截图、录屏打码只糊个人信息、文件链接这一小块（「全都糊成一片看啥」）；主人说不介意的就不打
